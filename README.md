# БАЗ

Вечіркова гра «вгадай мелодію» — але замість радіохітів грає плейліст одного з гравців.

Компанія 3–8 людей грає в одній кімнаті: один телефон відтворює звук вголос (ведучий), решта — «баззери». Ведучий приносить свій плейліст з YouTube Music, грає короткий фрагмент випадкового треку, і хто перший тисне БАЗ — вгадує виконавця/назву. Ведучий міняється між раундами.

Повний продуктовий бриф (механіка, аудиторія, зафіксовані рішення, скоуп) — у [CLAUDE.md](./CLAUDE.md).

## Структура репо

| Папка | Що там | Статус |
|---|---|---|
| [`research/`](./research/) | Продуктове дослідження: конкуренти, референси, нотатки з тестових ігор. Скріншоти — в `research/screens/`. | аналіз конкурентів готовий |
| [`concept/`](./concept/) | Ранні концептуальні напрямки, флоу, voice/тон до фіксації в wireframes. | перша чернетка флоу сесії |
| [`wireframes/`](./wireframes/) | Низькодеталізовані макети екранів (лоббі, host view, player view, стани помилок). | не розпочато |
| [`tokens/`](./tokens/) | Дизайн-токени: колір, типографіка, spacing, motion. | не розпочато |
| [`components/`](./components/) | UI-компоненти на основі токенів (кнопка БАЗ, картка гравця, плеєр ведучого тощо). | не розпочато |
| [`design-system/`](./design-system/) | Зведена система: правила застосування, патерни станів. | не розпочато |
| [`handoff/`](./handoff/) | Специфікації та assets для передачі в розробку. | не розпочато |

Порядок роботи зверху вниз: `research → concept → wireframes → tokens → components → design-system → handoff`. Технічна реалізація (frontend/backend) поки не має власної папки — з'явиться, коли стартує розробка MVP.

## Стек (з CLAUDE.md)

- Мобільний веб, mobile-first
- Джерело музики та відтворення: YouTube Data API v3 + YouTube IFrame Player API
- Реалтайм-кімнати: WebSocket (код кімнати, приєднання через інтернет)

## Статус

Продуктовий бриф зафіксовано. Аналіз конкурентів (ХАРД/СОФТ/АСПІРАЦІЙНІ) — в [`research/research.md`](./research/research.md). Дизайн і розробка MVP — не розпочато.
